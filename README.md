# VSF Merchant Management AI

VSF Merchant Management AI is a centralized platform for managing merchants, tracking operational metrics, parsing menus, storing customer/driver reviews, and maintaining spatial (Haversine-based) search capability for the VSF Merchant platform.

This repository is structured for collaborative team development with a clear separation between the **Frontend** and **Backend** architecture.

## Database Architecture

The system uses **PostgreSQL 18** with structured schemas mapped using **SQLAlchemy 2.0** ORM patterns:

1. **`merchants`**: Store basic metadata, location (lat, lng), and working hours.
2. **`menu_items`**: Menu catalog entries for each merchant with price, description, and cuisine/diet tags (stored as JSONB).
3. **`reviews`**: Customer reviews containing text, rating, sentiment classifications, and social interactions.
4. **`delivery_feedbacks`**: Feedback submitted by drivers regarding merchants (ratings, packaging comments).
5. **`food_images`**: Images associated with menus or stores, containing image quality scores (`dish_image_quality`, `blur_score`).
6. **`operational_metrics`**: Average preparation times and peak ordering hours.
7. **`merchant_profiles`**: Pre-calculated analytical dimensions generated by the scoring engine (food quality, service, image rating).
8. **`user_profiles`**: User dietary preferences, locations, liked/disliked cuisines, and conversation memories.
9. **`chat_sessions`** & **`chat_messages`**: Chat history and message streams between users and the merchant assistant agent.

## Team Setup & Database Installation

Follow these steps to deploy the database instance and apply the migrations:

### 1. Prerequisites
- Docker & Docker Compose installed.
- Python 3.10+ (or Conda environment).

### 2. Launch the PostgreSQL Container
Deploy the persistent, containerized PostgreSQL database using:
```bash
docker compose up -d
```
The database will be exposed on port `5432` with the default name `merchant_platform`. Data is persisted locally using Docker volumes.

### 3. Configure the Environment
Create a `.env` file in the root directory and specify the database variables:
```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=merchant_platform
DB_HOST=localhost
DB_PORT=5432
```

### 4. Apply Schema Migrations
1. Navigate to the `backend/` directory:
   ```bash
   cd backend
   ```
2. Install the core dependencies (ensure your virtual environment is active):
   ```bash
   pip install -r requirements.txt
   # Or install directly: pip install SQLAlchemy alembic psycopg2-binary
   ```
3. Run Alembic to apply all migrations and upgrade the database schema to the latest version:
   ```bash
   PYTHONPATH=. alembic upgrade head
   ```

### 5. Custom PL/pgSQL Spatial Function
The schema utilizes a server-side custom PL/pgSQL function named `haversine()` to compute geographical distances between coordinates directly inside PostgreSQL queries. This allows fast, indexable spatial searches without requiring third-party extensions like PostGIS:
```sql
SELECT haversine(lat1, lon1, lat2, lon2);
```

## Backend Contribution Guide
1. Define new tables or fields inside `backend/database/models.py`.
2. Generate a new database migration script using Alembic auto-generate:
   ```bash
   cd backend
   PYTHONPATH=. alembic revision --autogenerate -m "description_of_changes"
   ```
3. Apply the migration:
   ```bash
   PYTHONPATH=. alembic upgrade head
   ```
4. Always commit your migrations inside `backend/migrations/versions/` alongside your model updates.
